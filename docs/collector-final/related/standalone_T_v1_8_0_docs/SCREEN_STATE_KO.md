# 화면 멈춤 판단과 원인 진단 — 쉬운 설명 (v1.2)

수집기는 버튼을 누른 뒤 "화면이 다 떴나, 아직 뜨는 중인가, 멈췄나"를 스스로 봅니다. 멈췄으면 "왜 멈췄나"까지 프로그램으로 알아냅니다. AI는 거의 안 쓰고(애매할 때만 딥시크 1회), 화면·브라우저를 건드리지 않습니다. 법원·iros 주소로는 어떤 직접 요청도 하지 않습니다.

## 1. 화면 3가지 판단 (`standalone/screen_state.py`)
매 단계 뒤에 봅니다.
- **로딩 중** → 더 기다림: '처리중/조회중/잠시만/로딩/Loading/검색중' 글자가 있거나, 화면이 계속 바뀌거나(축소 회색 그림 비교), 빈 하얀 화면·반만 그려진 화면이면 아직 뜨는 중으로 봅니다. 사이트별 상한까지 기다립니다(법원 기본 60초).
- **다 됨** → 진행: 화면이 2~3번 연속(약 1.5초) 거의 같고, 기대한 글자나 조각그림이 보이면 완료입니다. 목록은 **표 줄 수가 2번 연속 같아야** 완료로 봅니다. (광고 움짤처럼 아주 작은 부분만 깜빡이는 건 '같음'으로 봐서 속지 않습니다.)
- **멈춤** → 로딩 표시가 없는데 화면이 그대로(기본 20초)이고 기대 글자도 없으면 멈춤 후보입니다.

멈춤 후보면: ① 먼저 오류표(page_guard)를 봅니다(오류코드면 그 대응). ② 아니면 **새로고침 없이** 한 번만 다시 확인합니다. ③ 그래도면 원인 진단(2번)으로 넘어가 기록·사진을 남기고 멈춥니다.

기준값은 사이트 JSON `screen`에서 **늘리기만** 됩니다(`load_max_sec`, `frozen_sec`, `settle_sec`, `settle_frames`, `min_content`). 기다린 시간은 `collector_kb/knowhow/screen_timing_local.json`에 사이트·단계별로 쌓여서, 다음엔 평소 걸리던 시간 아래로는 멈춤으로 보지 않습니다. 저장창(no_save_dialog)도 이 판단을 써서, 뷰어가 로딩 중이면 더 기다립니다.

## 2. 왜 멈췄나 원인 진단 (`standalone/stall_diag.py`)
순서대로 봅니다.
- **(A) 내 컴퓨터가 멈춤**: 피코로 마우스를 빈 곳에서 몇 px 움직여 보고, 커서 위치나 작업표시줄 시계가 바뀌는지 봅니다. 안 바뀌면 **PC_FROZEN**(사진·기록 후 멈춤). 이때 NTP(3번)도 한 바퀴 돌려 시계 점프를 봅니다. 노트북이 잠깐 멈췄다 깨어난 것(시계가 갑자기 30초 넘게 튐)은 **PC_HICCUP**으로 기록하고, 끊지 않고 한 번 더 확인합니다.
- **(B) 자료는 오는 중**: `psutil`로 받은 바이트가 5초 동안 늘고 있으면 **DATA_FLOWING** → 더 기다립니다(상한을 늘림).
- **(C) 보냈는데 응답 없음**: 받은 바이트가 안 늘면 배경으로 ①기본 게이트웨이 ping ②DNS 조회 ③중립 사이트 연결(브라우저 안 염: msftconnecttest / generate_204)과 NTP(3번)를 종합합니다.
  - 인터넷이 되는데 이 사이트만 응답 없음 → **SITE_NO_RESPONSE**(5xx처럼 30분 쉬고 다음 회차에 1번 재시도). 사이트 JSON `site_alive_check:true`면(법원·iros 제외) 상대 서버에 HEAD로 생사만 더 확인합니다.
  - 게이트웨이는 되는데 바깥이 안 됨 → **ISP_DOWN**.
  - 게이트웨이도 안 됨 → **LOCAL_NET_DOWN**(와이파이/선).
  - ISP/LOCAL은 5분 간격으로 확인하며 기다리다, 복구되면 그 화면부터 다시 합니다.

진단 결과는 사진과 함께 기록하고, 사이트별 통계를 `collector_kb/knowhow/stall_stats_local.json`에 쌓습니다. 결과가 애매할 때만(UNKNOWN) 딥시크에 기록 요약을 1회 물어봅니다(사이트 주소·비밀값은 보내지 않음).

## 3. 지역별 NTP 확인 (`standalone/sntp.py`)
화면·브라우저를 안 건드리고 UDP 123(SNTP 48바이트, 서버당 2초)으로만 선로·인터넷·시계를 봅니다. 법원·iros 로는 보내지 않습니다.
- 지역 묶음(기본, 설정으로 **늘리기**만): 국내(time.kriss.re.kr, time.bora.net, kr.pool.ntp.org) → 일본(ntp.nict.jp, jp.pool.ntp.org) → 동남아(sg.pool.ntp.org, asia.pool.ntp.org) → 미국(time.google.com, time.cloudflare.com, us.pool.ntp.org) → 유럽(europe.pool.ntp.org, de.pool.ntp.org).
- **한 대만 무응답 = 서버 한 대 장애(SERVER_DOWN)**, **그 지역 전부 무응답 = 그 방향 선로 차단(REGION_BLOCKED)**, **모든 지역 무응답 = 우리 쪽 인터넷 끊김(ALL_DOWN)**.
- 평소 10분마다 1지역씩 순환, 멈춤 의심 때 즉시 한 바퀴. 연속 요청은 하지 않습니다.
- 받은 NTP 시각과 노트북 monotonic 경과 차이가 갑자기 크게(기본 30초) 벌어지면 PC_HICCUP으로 봅니다.

## 4. 켜고 끄기 (설정)
- **`ntp_check`** (전체 `config.json`, 기본 **켜짐**): 멈춤 진단에서 NTP 확인을 쓸지.
- **`site_alive_check`** (사이트 JSON마다, 기본 **꺼짐**): 완료 못 한 사이트의 상대 서버에 HEAD로 생사 확인. **법원·iros는 켜도 거부**(규칙).
- 첫 실행 `python -m standalone keys` 끝에 이 두 가지를 물어보고, `config.json`/사이트 JSON에 넣을 값을 알려줍니다(keys는 비밀값만 저장하므로 값은 손으로 넣어요).

## 5. 가짜 화면 시험 (사이트 접속 없음)
`tests/test_standalone.py`에 넣었습니다: 로딩→완료, 멈춤, 하얀 화면(로딩으로 봄), 광고 깜빡임에 안 속기, 기준값 늘리기만; 원인 진단(PC 멈춤·자료 흐름·사이트 무응답·인터넷 끊김); NTP(한 대 장애·지역 차단·전체 끊김·시계 점프·지역 늘리기); 법원은 site_alive_check 켜도 HEAD 안 함.
