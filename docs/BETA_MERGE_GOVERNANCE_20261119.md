# BIDGUARD 베타 시험·병합 제1원칙 (관리인 확정 2026-11-19)

> 적용 대상: 현재 개발·가동 중인 **관제기, 수집기, PWA, 노트북 서버, 게임, 회원/포인트, 지도, 데이터/백업** 등 모든 BIDGUARD 시험 시스템. 낡은 노트북에서 시험 운영 중이라는 사실은 상업용 출시를 의미하지 않습니다.

## 1. 개발/베타는 모든 기능을 시험한다
- 별도 지시가 없는 한 가능한 기능을 구현하고 실제 시험합니다. 임의 삭제, 상업용 심사 명목의 관행적 보류를 하지 않습니다.
- 기존 기능을 보존하고 통합합니다. 중복 기능은 스택 구조·원장·데이터 마이그레이션 영향을 검수해 결정합니다.
- 법률·기술·안전 위험은 **경고와 근거, 재현 조건, 보완책**으로 기록하고 베타 기능 실험을 개선합니다. 경고 자체가 자동 폐기 명령은 아닙니다. 실제 비밀 유출, 승인 없는 타인 시스템 조작 등 불필요한 피해는 시험 환경에서 차단합니다.
- 모의·합성 데이터와 승인된 장치를 이용하여 공격/방어/장애·복구 시나리오를 포함해 검증합니다.

## 2. 최종 GitHub 병합 결정 = ChatGPT
- **Claude, Gemini, Grok 및 기타 개발 봇**은 PR 작성, 코드 제안, 자가 시험, 리뷰 자료와 위험 경고를 제출할 수 있습니다.
- **최종 병합(Merge)/폐기 판정 권한은 ChatGPT**에 있습니다. 봇은 독자적으로 main에 병합·배포하지 않습니다.
- ChatGPT는 PR 차이, 기존 코드, 종속 브랜치, 테스트 근거를 검수한 뒤 가능한 안은 **바로 베타 main에 병합**합니다. 자동으로 모든 PR을 승인하는 원칙은 아닙니다.
- 이미 논증되어 필요 없어진 초안은 근거를 댓글에 남기고 종료합니다. 기능이 더 최신 통합판에 포함된 경우에는 **기능 폐기 아님·중복 PR 종료**로 구분합니다.
- 판단이 어려운 사항(서로 상충하는 제품 정책·데이터 의미·역할/인증 정책 등)은 관리인에게 확인한 뒤 결정합니다. 단순 개발 충돌은 우선 기술적으로 해결합니다.

## 3. GitHub·비용·자료
- 공개 저장소: 소스·시험 코드는 게시할 수 있지만 **실제 암호, API 키, 지갑 파일, 회원정보, 원본 경매 실데이터, 비공개 로그를 커밋하지 않습니다.**
- 기사·영상·지도 실데이터를 반복적으로 GitHub Actions에 올리거나 데이터 배포 목적으로 CI를 남발하지 않습니다. 검증된 자료는 정해진 서버 DB/관제기로 직접 전송하는 구조를 우선합니다.
- 기능 개발·검증 때 무료 도구를 우선하며 유료 호출이 필요한 경우 기존 비용 상한을 준수합니다.
- **GitHub main 병합 ≠ 관제기/노트북 실제 설치 완료.** 해당 서비스의 버전·헬스체크·실기기 동작을 검증하고 병합/배포/시험 결과를 각각 분리 기록합니다.

## 4. 상업용 출시와 별개
- 현재 구현·시험은 상업용 서비스 승인으로 해석하지 않습니다.
- 정식 출시 여부는 향후 관리인의 별도 전환 지시, 변호사와 해당 기관 등의 필요한 검토·승인 절차에서 결정합니다.
