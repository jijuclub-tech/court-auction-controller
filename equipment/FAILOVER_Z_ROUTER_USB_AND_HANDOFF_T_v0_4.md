## 1. 관제기의 의사 결정 순서

1. **현장 수집기에서 파일을 수신·저장하는 즉시 로컬 spool 및 manifest를 내구적으로 보관**: node_id, job_id, 사건번호/물건/문서종류, 파일버전, source_url, captured_at, sha256, bytes, 원본 경로, 재전송/저장 이벤트.
2. NAS X:의 진짜 공유 대상, 접근 권한, 유효한 저장, 원격 읽기/해시를 확인한 경우 NAS에 검증 복사한다. **PC가 켜져 있거나 X: 문자가 보이는 것만으로 NAS 정상 아님**.
3. NAS가 불능이고 PC에서 Z: 공유기 USB 접근이 확인된 경우, 각 PC 단독의 임시 폴더를 Z: 아래 전용 node_id/job_id 경로로 복사한다. 버전/해시 충돌을 덮어쓰지 않는다. 관제기 DB에는 ROUTER_USB_STAGED 및 NAS_PENDING으로 기록. 원본 로컬 유지.
4. Z: 접근 불가 시 Google Drive 암호화 백업을 시도한다(백업 성공은 원격 읽기/검증 통과 기준). 해당 PC가 외부 지역이면 Z: 접근을 기본값으로 가정하지 않는다. 별도 인증 HTTPS/Tailscale 경로가 마련된 경우에만 접근한다.
5. NAS 정상 복귀 시 각 장비 PC spool 및 Z: 임시 폴더의 manifest를 관제기가 집계하고 **NAS에 없는 파일만** 해시/크기/권한 검증 후 이관한다. 기존 파일 수정/삭제 금지; 사본 검증 완료 전 임시 파일 폐기 금지.

## 2. NAS/Z/Drive 이중·삼중 장애에 따른 관제 결정표

| 상황 | 저장/업무 결정 | 알림 | 재분배 |
| --- | --- | --- | --- |
| NAS 정상, 수집기도 정상 | 로컬 spool 후 NAS/Drive 각각 검증 | 경고 없음 | 불필요 |
| NAS 장애, Z USB 정상, 로컬 충분 | Z:에 격리 임시저장 + Drive 백업, 수집 계속 | NAS 불능·Z 임시전환 즉시 경고 | 원칙적으로 불필요 |
| NAS/Z 동시 장애, 로컬 충분, Drive 정상 | 로컬 및 Drive 별도 보관, 작업 계속/속도 제한 | 백업 경로 감소 경고 | 원칙적으로 불필요 |
| NAS/Z/Drive 장애, 로컬 충분 | 정책 한도 내 임시 수집 또는 관리자 확인까지 유예 | 매우 높음 | 대체 수집기 저장 상태 확인 |
| 로컬 공간 임계치, 파일시스템 오류, 원본 무결성 불확실 | 신규 수집 안전 정지, 진행 중 원본 보전 | 즉시 긴급 | 인증/저장 정상인 다른 PC에 미시작 작업 배정 |
| 수집기 서비스 고장/장시간 응답 없음 | lease 종료와 체크포인트/ACK 확인 | 즉시 장애 경고 | 권한·법원·지역·작업량 조건으로 재할당 |
| NAS 복구 | Z + 로컬 누락/충돌 목록·해시 대조 → 재이관 | 복구/잔여 누락량 보고 | 중단 작업 재개 검토 |

**금지:** 특정 PC가 로그인한 사이트 세션을 다른 PC로 무조건 넘기기, 같은 사건/문서 동시 수집, 보안·접근제한 우회, 완료 ACK 전에 작업 중복 시작, NAS 오류 직후 로컬 원본 자동삭제.

## 3. ipDISK / 공유기 USB(Z:) 식별 및 검증

- 사용자 보고: Z:는 공유기에 연결된 USB 공유 저장장치. 같은 LAN에서 NAS로 복사하기 쉬운 장점이 있지만, NAS가 정지되어 있으면 이관은 복구 후에 가능하다.
- Windows 매핑: GetDriveType=remote와 실제 원격 연결 정보를 대조. 네트워크 drive 문자만 믿지 않고 원격 share/장치 identity 확인. ipDISK 프로그램의 가상 드라이브일 수 있으므로 해당 장치의 실제 파일 읽기·쓰기 증거가 필요하다.
- 경로는 환경설정의 허용 목록으로 한정. Z: 임시저장은 node_id/job_id가 격리되고 인증된 PC만 접근한다. 폴더 경로/파일명 정규화, 경로 이탈 금지, 임시 업로드와 원자적 rename, SHA256 read-back, 파일 권한, 용량상한, 쓰기시간 제한.
- 공유기 USB 스토리지의 성능 및 내구성이 NAS와 같다고 가정하지 말 것. 공유기·네트워크 장애의 공통 실패 영역을 고려해 Z:만을 독립 원격 백업으로 인정하지 않는다.
- NAS 복구 직후의 대량 이관은 속도 제한을 두고 여유 공간/작업 우선순위를 기준으로 분할한다.

## 4. 업무 인계 = 상태·저장·권한을 함께 판단

- 기존 collector_dispatch의 중앙 job key, 원자적 lease/ACK/fencing, 일정 및 지역 분담을 재사용한다. 기존 1호 서울/2호 제주 정책을 임의 변경하지 않는다. 3호는 별도 등록된 실제 능력·업무 범위 확인 후 배정.
- 관제기는 원본/임시 저장 manifest, 완료 문서 SHA, 마지막 확정 단계, 예약 중인 업무/기기 상태, 디스크 여유, 담당 지역 및 사이트 접근권한을 확인한다.
- 원래 PC가 살아 있고 Z 또는 Drive에 안전한 복사본이 있다면 **불필요한 인계보다 안전한 지속**을 우선.
- 원래 PC가 중단되면 **확인된 미완료 작업만** 다른 기기에 재배정한다. 중간 클릭·결제·인증·다운로드 중에 다른 기기로 즉시 세션을 넘기지 않는다. 위험 작업은 관리자 승인 필요.
- 인계에는 old_node, new_node, job_id, lease_generation, checkpoint_hash, requested_at, acknowledged_at, reason, permissions_check 등 사건 이력을 남긴다.
- 관제기 화면에서는 '계속 수집 / 속도 제한 / 안전 중지 / 대체 수집기로 재배정 / 관리자 확인' 결정을 한눈에 보여준다. 자동 결정과 관리자 수동 변경 모두 감사로그 유지.

## 5. PC별 바탕화면·주요 아이콘 기준본 (비상 복구용)

- 설치/등록 시 운영자 승인하에 **각 PC 자체에서** 기준 스냅샷을 생성: 디스플레이 크기/배율/모니터 배치, 주요 단축아이콘 이름/위치·프로그램 식별자 및 필수 프로세스/버전, 필요한 범위의 바탕화면 모습(민감 부분 마스킹), 작업에 사용한 기본 디렉터리/복원 순서.
- 무분별한 화면 녹화/주기적 개인 화면 캡처는 금지. 기본은 메타데이터, 시각 이미지 필요 시 관리자 명시 승인. 작업 중 로그인 화면/계좌/고객 문서는 촬영·보관 금지.
- 기준본은 운영자 전용 암호화 로컬 저장, NAS·Drive에 암호화된 백업, 이전 버전 해시 및 변경 사유 보존. 공개 GitHub에는 *가짜 예시/스키마*만.
- 비상 상황에서 관제기 삼성 탭 UI에 해당 PC의 기준본과 현재 서비스 상태를 비교해 복구 가이드를 제공. 관리자 승인 없는 키/마우스 원격조작은 포함하지 않는다.

## 6. 시험과 완료 판정

1. NAS 정상/장애/복구, Z USB 정상/용량부족/접근 실패, Drive 단절을 합성 시험 후 실기 시험.
2. NAS OFF + Z ON → 검증된 1건 stage, LOCAL/NAS_PENDING/ROUTER_USB_STAGED 표기, NAS 회복 → 누락분 NAS 전송, 무결성 PASS, 원본 보존.
3. X: 또는 Z:가 로컬 subst일 때 거짓 성공 0. Z와 NAS가 같은 공유기 장애를 겪을 때도 local/Drive 경로 유지.
4. 2대 이상 수집기에 동일 업무 자동 인계 시험. 원자 lease/ACK 준수, 중복 작업·중복 저장 0.
5. PC 바탕화면 기준본의 권한/암호화/마스킹/복원 시연 1회. 화면 원문·비밀키 GitHub 업로드 0.
6. 삼성 탭에서 경보·인계 결정 및 관리인의 확인/복구 후 최종 상태 표시.
7. 실제 NAS/USB/PC/Drive 연동 증거가 없으면 DONE/PRODUCTION으로 표시하지 않는다. Claude 읽기 전용 검수 → Grok 최종 통합, ChatGPT 관제 설계/서버 연계.

## 구현 단위
- P0-1: 저장 대상 registry 및 X/Z 로컬 여부 검증, local→Z outbox/manifest 전송.
- P0-2: NAS 복구 감지 + Z/local 대기 항목 해시 대조 이관 + Drive 별도 백업 정합성.
- P0-3: 실행 작업 lease/checkpoint에 저장 상태를 추가해 수집 계속·중단·대체 기기 인계를 결정.
- P1-1: 장비별 바탕화면 기준본/단축아이콘 위치/프로그램 버전 복구 메타데이터.
- P1-2: 삼성 탭 /admin에 장비별 저장 위치·누락건·인계 사유/승인/이력 카드.

**주의:** 이 설계서만으로 기존 수집기/관제기가 자동 변경되지 않는다. 구현/테스트/운영배포를 별도 기록한다.
