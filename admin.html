관리인 호출 · 관제기 질문

3단계(관제기 질문)는 글록 봇이나 관리인이 답합니다. 4단계(관리인 호출)는 관리인만 답합니다. 화면을 누르면 그 자리를 클릭하라는 답이 됩니다. 아이디·암호·보안문자 답은 '글자 입력'으로 보냅니다 — 관제기에 저장되지 않고, 수집기가 한 번 가져가면 지워집니다.

최근 답한 호출

수집기

처음 접속한 수집기는 '등록 대기'로 나옵니다. 승인해야 지시·갱신·호출을 주고받습니다. 상태는 수집기가 단계 사이마다 보내는 보고입니다.

수집기 미리 등록

메뉴 — 자주가는 사이트 / 기타 사이트

수집기의 '관제형' 탭 메뉴가 이 목록을 따릅니다. 수집기에서 직접 추가한 사이트는 그 PC에만 남습니다.

정해진 경로

경로 = 사이트에서 차례로 할 단계들. 각 단계의 '시작 단계'는 AI 사다리를 몇 단계부터 쓸지입니다(보통 1, 단추를 골라야 하면 2). 실행기 'auto_flow'는 글록 수집기를 그 단계에 씁니다.

사이트

AI 단계

1단계 로컬 Ollama·딥시크 / 2단계 하위 AI / 3단계 관제기(기본, 보급형에는 안 보냄)·글록 봇·사용자·쳇GPT·클로드·상위 모델 / 4단계 관리인. 관제기와 연결이 안 되면 수집기는 바로 4단계로 갑니다. 꺼진 칸은 부르지 않고 지나갑니다.

학습서 — 누가 쓰고 누가 검수하나

수집기가 다녀온 기록(어느 화면에서 무엇을 눌렀고 성공했는지, 걸린 시간, 뜬 알림창)을 관제기가 단계별로 센 다음, 작성 AI가 사이트별 학습서를 쓰고 검수 AI가 문제만 지적합니다(고쳐 쓰지 않음). 관리인이 승인해야 수집기에 갑니다. 수집기가 "이 사이트에 들어갑니다"라고 알리면 승인된 최신 학습서를 받습니다. 학습서의 단계마다 '쉬움'이면 1단계(딥시크 등)부터, '어려움'이면 2단계(제미나이 등)부터 AI를 씁니다.

작성 AI 검수 AI
기록이 건 새로 쌓이면 자동으로 만들기 (0 = 관리인이 누를 때만)

AI별 방식 · 모델 · 키

글록은 '봇'(글록 봇이 관제기에서 일을 가져감, 봇 토큰 사용) 또는 'API'(xAI 키)로 씁니다. 나머지는 API 키로 씁니다. 키는 관제기 자료 폴더의 관리인 전용 파일에만 두고 화면에 다시 보여 주지 않습니다. 설정 파일(controller.env)에 넣은 키도 씁니다.

만드는 중 · 최근 작업

학습서 판

새 판은 먼저 한 수집기에서 '시험'하고, 성공률이 그대로이거나 좋아지면 '전체 적용'합니다. 나빠지면 이전 판을 다시 '전체 적용'하면 됩니다. 판마다 성공률은 수집기가 그 판을 쓰는 동안 보낸 기록으로 셉니다.

지시서 (기존 관제형 지시)

수집기의 Collect 탭(관제형)이 받아서 사건번호별로 수행하고 결과를 보고합니다.
