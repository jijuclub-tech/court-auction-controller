1. 네트워크 대체 실행을 없앤다. 온라인이 필수다. 관제기에 연결되지 않으면 실행하지 않고, '로컬 DB로 계속'과 '최소 지도' 예외도 없앤다.
   멈춘 사유를 분명히 남긴다. 작업 중 잠깐 끊기면 stall_diag 복구 대기 뒤 같은 화면에서 이어간다(새 작업 시작 안 함).
2. 큰 사진(화보)이 필수다. 사이트 지도마다 고해상도 전체 화면 사진을 넣고, 단계별 대표 화보를 저장·내려받는다.
   조각·2·4·8배와 함께 '전체 화면' 크기 등급을 둔다. 화보에서도 ID/PW/캡차 칸은 가리고, 금지 그림(인증서)은 따로 둔다.
3. 사이트 용량 등급: A 500MB(핵심), B 100MB, C 10MB(대부분), D 1MB. 관제기가 관리하지 않는 사이트는 최대 100MB, 기본 C.
   등급·사용량은 매니페스트(site_id, grade, version, files, sha256, bytes)로 정한다. 법원경매는 기본 A(설정으로 바꿈).
4. 흐름: 실행 → 관제기 연결(필수) → 사이트 참고자료(화보 포함) 받기 + SHA 확인 → 화면에 '해당 사이트 학습 중입니다…' →
   전부 메모리 적재 → 작업 중에는 메모리 자료만 → 끝나면 메모리 해제. 디스크 캐시는 받는 동안의 임시 용도, 같은 버전은 다시 받지 않는다(SHA 확인 후 메모리로).
5. 용량을 넘으면 중복·유사 화보(지각 해시 거리)부터, 그다음 오래된 것을 정리한다. 대표 화보와 성공률 상위는 보호한다.
   정리 내역은 관제기 보고 JSON 에 남기고, 올리기 전에도 등급 한도를 지킨다.
6. SERVER_API_KO.md 에 엔드포인트(매니페스트, 파일 받기, 사용량·정리 보고)를 적고 가짜 서버로 시험한다.
