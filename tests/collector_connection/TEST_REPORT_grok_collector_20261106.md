## 2. 시험 방법

### 실행
```bash
bash tests/collector_connection/run_all_tests.sh
```
- 저장소의 `controller/`와 `new_collector/`를 **임시 폴더에 복사**해서 시험 (원본 폴더에 파일이 생기지 않음).
- 관제기(Flask)를 실제로 띄우고(127.0.0.1:8099), 수집기 코드가 실제 HTTP로 연결·지시 수령·결과 보고.
- 필요: Python 3.10 이상, `flask`, `cryptography`, `requests`.

### 대역(가짜)으로 대신한 것
- **화면 부품(tkinter)**: 시험 서버에 tkinter가 없어 `fake_tk/`의 대역 사용. 글자·버튼·입력값만 흉내내고 창은 그리지 않음. 연결·지시·보고 로직은 실제 코드 그대로 실행.
- **감정평가서 모듈의 대기 시간(20초 이상)**: 시험 시간을 줄이려고 `core/appraisal.py` 안의 대기만 생략. 다른 모듈의 대기는 실제로 기다림.
- `human_input.py`, `captcha.py`, `login.py`는 **대역 없이 실제 코드**로 시험.

## 4. 발견 사항 (고치지 않고 기록만)

1. **로그에 비밀번호가 남음** — 로그인 때 `HumanHID`가 보내는 키가 한 글자씩 INFO 로그로 기록됨. 시험 비밀번호 `Pw#9z`가 Log 탭·콘솔에 그대로 찍힘 (`human_input.py`의 `_simulate`).
2. **`captcha.py`가 어디에도 연결되지 않음** — 다른 파일이 `CaptchaHandler`를 사용하지 않음. 실제 다운로드 흐름(`appraisal.py`)은 자체 `handle_view_dialog()`를 쓰며 항상 성공을 반환(시뮬레이션). "시도 후 사용자 호출" 원칙이 실제 흐름에는 아직 적용되지 않음.
3. **피코2로 실제 신호가 나가지 않음** — `HumanHID`의 기본 전송이 로그 기록(`_simulate`)뿐. 감정평가서는 시험용 빈 PDF 생성, `map/courtauction_map.md`는 경로만 지정되고 읽지 않음.
4. **로그인 버튼 누르면 창이 약 3초 멈춤** — `do_login()`이 화면 스레드에서 사람처럼 타이핑(대기 포함)을 수행.
